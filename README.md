# codeknowledge (ck)

> AI-ready knowledge graph for your codebase. Analyze any repo once, query it forever — dramatically reducing token consumption when AI agents work on unfamiliar or large codebases.

## How it works

1. **Parse** — tree-sitter AST extracts files, classes, functions, and import edges
2. **Graph** — builds a graphology directed graph (nodes = code units, edges = imports/calls/inherits)
3. **Summarize** — Anthropic claude-haiku generates a 3-5 line semantic summary per file (once, cached by hash)
4. **Persist** — saves `graph.json` + per-folder `SUMMARY.md` in `.codeknowledge/`
5. **Query** — fast structural queries + LLM natural language queries over the graph
6. **Watch** — git-aware incremental re-index of only changed files

## Install

```bash
cd your-project
npm install -g codeknowledge   # or: npx codeknowledge
```

## Quick start

```bash
# 1. Initialize config
ck init

# 2. Index your codebase (graph only, no LLM)
ck index --no-summaries

# 3. Index with LLM summaries — pick one:
ANTHROPIC_API_KEY=sk-ant-...  ck index   # Anthropic (recommended, cheaper)
OPENAI_API_KEY=sk-...         ck index   # OpenAI fallback

# 4. Query the graph
ck query "where is authentication handled?"
ck query "who uses AuthService?"
ck query "impact of src/auth/AuthService.ts"

# 5. Check status
ck status

# 6. Watch for changes (incremental updates)
ck watch
```

## CLI reference

| Command | Description |
|---------|-------------|
| `ck init` | Scaffold `.codeknowledge/` config |
| `ck index [paths...]` | Full index of current directory or specific paths |
| `ck index --force` | Re-index all nodes even if unchanged |
| `ck index --no-summaries` | Graph only, skip LLM calls |
| `ck index --no-markdown` | Skip SUMMARY.md generation |
| `ck query "<question>"` | Natural language or structural query |
| `ck status` | Show graph stats and stale nodes |
| `ck watch` | Watch mode: incremental updates on file change |
| `ck serve` | Start MCP server on stdio (for Cursor / Claude Code) |

## Query syntax

```bash
# Natural language (uses LLM if ANTHROPIC_API_KEY is set, else text search)
ck query "where is JWT validation handled?"

# Structural: find usages
ck query "who uses AuthService"
ck query "find usages of parseFile"

# Structural: impact analysis
ck query "impact of src/core/graph/index.ts"
ck query "what breaks if src/utils/hash.ts changes"
```

## Configuration

Create `ck.config.js` in your project root (auto-generated by `ck init`):

```js
module.exports = {
  // LLM provider — "anthropic" | "openai"
  // Auto-detected from env vars if omitted (Anthropic wins if both keys are set)
  provider: "anthropic",
  model: "claude-haiku-4-5",           // or "gpt-4o-mini" for OpenAI

  // API keys — set via environment variable (never hardcode)
  apiKey: process.env.ANTHROPIC_API_KEY,     // for provider: "anthropic"
  openAIApiKey: process.env.OPENAI_API_KEY,  // for provider: "openai"

  include: ["src/**", "lib/**"],
  exclude: [
    "**/*.test.*",
    "**/node_modules/**",
    "**/*.d.ts",
    "**/dist/**",
  ],
  languages: ["typescript", "javascript", "python", "go"],
  maxFileSizeKB: 200,

  summaries: true,
  summaryMaxLines: 200,               // max lines sent to LLM per file

  outputDir: ".codeknowledge",
  generateMarkdown: true,             // generate SUMMARY.md per folder

  mcpPort: "stdio",
};
```

### Setting your API key

**Anthropic** (recommended — cheapest for summarization):
```bash
export ANTHROPIC_API_KEY=sk-ant-...
# Get yours at: https://console.anthropic.com/
```

**OpenAI** (alternative):
```bash
export OPENAI_API_KEY=sk-...
# Get yours at: https://platform.openai.com/api-keys
```

Add the export to your shell profile (`~/.zshrc`, `~/.bashrc`) to make it permanent. `ck` auto-detects which key is available — no need to change `ck.config.js`.

| Provider | Model | Notes |
|----------|-------|-------|

## Output: `.codeknowledge/`

```
.codeknowledge/
├── graph.json          # full knowledge graph (nodes + edges)
├── summaries.json      # LLM summary cache (keyed by file hash)
├── config.json         # effective config
└── src/
    ├── SUMMARY.md      # auto-generated per folder
    └── core/
        └── graph/
            └── SUMMARY.md
```

### `graph.json` schema

```json
{
  "version": "1",
  "generated_at": "2024-01-15T10:00:00Z",
  "nodes": [
    {
      "id": "src/auth/AuthService.ts",
      "type": "file",
      "language": "typescript",
      "path": "src/auth/AuthService.ts",
      "name": "AuthService.ts",
      "lines": [1, 85],
      "summary": "Handles JWT authentication...",
      "hash": "sha256...",
      "last_indexed": "2024-01-15T10:00:00Z",
      "stale": false,
      "exports": ["login", "logout", "verifyToken"],
      "tags": ["auth", "jwt", "service"]
    }
  ],
  "edges": [
    {
      "source": "src/api/routes.ts",
      "target": "src/auth/AuthService.ts",
      "type": "imports",
      "via": "import { AuthService } from '../auth/AuthService'"
    }
  ]
}
```

## MCP server — Cursor & Claude Code integration

`ck serve` starts a fully-featured MCP server on stdio, giving AI agents direct access to the knowledge graph without reading raw files.

### Setup for Cursor

1. Index your project once:

```bash
cd /path/to/your/project
ck index                          # graph only
ANTHROPIC_API_KEY=sk-ant-... ck index  # with LLM summaries (recommended)
```

2. Add to your Cursor `mcp.json` (Settings → MCP → Edit Config):

```json
{
  "mcpServers": {
    "codeknowledge": {
      "command": "npx",
      "args": ["codeknowledge", "serve"],
      "cwd": "/path/to/your/project"
    }
  }
}
```

Or if installed globally:

```json
{
  "mcpServers": {
    "codeknowledge": {
      "command": "ck",
      "args": ["serve"],
      "cwd": "/path/to/your/project"
    }
  }
}
```

3. Restart Cursor and use `@codeknowledge` in Composer/Chat.

### Setup for Claude Code

```bash
claude mcp add codeknowledge -- ck serve
```

Or add to `~/.claude.json`:

```json
{
  "mcpServers": {
    "codeknowledge": {
      "command": "ck",
      "args": ["serve"],
      "cwd": "/path/to/your/project"
    }
  }
}
```

### Available MCP tools

| Tool | Description |
|------|-------------|
| `ck_overview` | High-level repo summary: stats, languages, entry points, key modules |
| `ck_get_node` | Summary + deps + dependents for any file/class (e.g. `src/auth/AuthService.ts`) |
| `ck_find_usages` | Who imports or calls a symbol? (e.g. `AuthService`, `useAuth`) |
| `ck_impact` | Blast radius analysis: what breaks if I change this file? (up to 3 hops) |
| `ck_entry_points` | List all root files with no incoming imports |
| `ck_query` | Natural language question answered with LLM + graph context |

## Incremental watch mode

```bash
ck watch
# → Listening for changes...
# → File changed: src/auth/AuthService.ts
# → Re-indexed 3 nodes in 0.8s
```

Watch mode:
1. Detects file changes via chokidar
2. Hashes new content, compares with graph
3. Marks changed node + 1-hop importers as stale
4. Re-parses + re-summarizes only stale nodes
5. Saves graph + regenerates affected SUMMARY.md

## Design principles

- **Local-first** — no cloud storage, no telemetry, no required auth except LLM key
- **Human-readable** — `graph.json` is pretty-printed; `SUMMARY.md` files are committable docs
- **Cost-efficient** — hash-based cache means LLM is called only once per unique file version
- **Resilient** — never crashes silently; logs errors with path + reason, continues indexing
- **Graceful degradation** — if no API key, builds graph without summaries and warns user
